# 目标源优先与最小改动 v9.5

## 适用场景
所有新写源、改源和优化成品源的任务。

## 决策顺序
1. 读取目标站当前 URL、分类页、详情页、播放页或 API 返回体。
2. 记录当前行为基线：接口返回条数、字段完整性、线路数量、剧集数量、最终媒体地址和 HTTP 结果。
3. 将目标站实测结果与模板、策略、历史案例逐项对照。
4. 结构完全一致时复用设计；结构不一致时只复用通用思路，并重新适配字段、路由和选择器。
5. 对成品源只修改已被用户反馈或测试确认的问题，不因代码风格差异重写可用逻辑。
6. 修改后重新执行同一组基线检查，比较条数、字段、线路、播放地址和错误率，确认没有功能回退。

## 冲突裁决
目标站当前实测 > 用户明确要求 > 主技能契约 > 专项策略 > 类型模板 > 历史案例 > 默认假设。

## 禁止
- 未分析目标站就套用模板。
- 把“写法不同”直接判定为缺陷。
- 用未验证的旧选择器、域名、token、密钥或播放地址。
- 为修复局部问题改动无关接口。

## 最低验收记录
至少保留一个分类样本、一个详情样本、一个播放样本；记录修改前后列表条数、核心字段、线路数和最终媒体 URL。缺少网络或运行环境时，必须标记为未验证。
