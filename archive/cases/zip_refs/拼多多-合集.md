# 拼多多.py：data-preview 直链站模式 + 性能教训（2026-08-24）

`/opt/data/archive/xbpq资料/拼多多.py`（json 转 py，播放链接替换版）。
用户原需求：JSON 的"链接"字段直接取播放地址（`data-preview` 属性），`https://ckbhm3u8.vip/` 前缀替换成 `https://ckbhm3u8.com/`；该给二级给二级、该给一级给一级。

## 站点结构（色多多/拼多多，sddww 系）

- **域名候选**（多域名同站，`nlet.sddww.com` 会 301 到 `se-duo-duo-l3s2.sddww.xyz`）：
  `https://ca4j.sddww.xyz` / `https://epgo.sddww.xyz` / `https://nlet.sddww.com` / `https://sddww.xyz`
  - 域名测活标准：GET `/` 返回 200 且含 `models-videos__col`（首页就有 28 张卡，根路径可用——与 18j 不同）
- **列表卡片**：`<div class="models-videos__col">` 块（首页 28 个/页）
  - 链接：`<a href="/?play-56117-1-.html">` ← **注意末尾 `-`**，重拼 URL 时保留原分隔符
  - 标题：`<p class="mb-1"><a href="...">标题</a></p>`
  - 图片：`<img src="https://ckbhjpg.top/upload/...png">`（jpg/图片域是 ckbhjpg.top，与播放域 ckbhm3u8 不同）
  - **播放：`<img ... data-preview="https://ckbhm3u8.vip/20251119/qLW7tAtU/index.m3u8">`** ← 播放地址直接嵌在列表卡片 img 的 data-preview 属性里（同黄果 data-play-src 一类：自定义 data 属性直链 m3u8）
- **URL 格式**：
  - 分类：`/?fenlei={分类名}&p={pg}`（分类名是中文，直接用，requests 自动编码）
  - 详情：`/?play-{vid}-{pg}-.html`
  - 搜索：`/?search={wd}&p={pg}`（GET，返回 28 条 data-preview）
  - 最新视频：`/?video={pg}.html`；热门标签：`/?tags-ch-all.html`（162 个分类一次拿全）
  - 推荐类型下拉：`/?categories=1.html`（分类名链接同样 `/?fenlei=xxx`）
- **播放链接替换**（用户明确要求）：`re.sub(r'https://ckbhm3u8\.vip/', 'https://ckbhm3u8.com/', url)`——旧 CDN 域名失效，必须换新域。同类还有 ckbhm3u8.vip→com 这种"域名后缀轮换"模式（不同于 t26/t30→t33 的节点替换，这里是完整域名换后缀）

## ⚠️ 性能教训（用户"好慢啊"打回）

**homeContent 绝不能遍历所有分类逐个发请求**：第一版遍历 26 个分类每个 GET 一次（26×2-3s = 50s+），用户直接喊"好慢啊"。
修复后：homeContent 只 GET 主页 1 次解析 28 条推荐（~1s）；分类页由 categoryContent 按需请求；init 的分类列表抓取也只请求 tags-ch-all.html 一次正则全量提取。

## ⚠️ 羊壳环境 bs4 依赖

交付 py 时用了 `from bs4 import BeautifulSoup` → 本机没装 bs4 直接挂；羊壳环境同样**不保证有 bs4**（同 Crypto 教训）→ 改纯正则解析（`re.split(r'<div class="models-videos__col">', html)[1:]` 按卡切块）。黄果用户重写版用 bs4 是用户自己的选择，交付给壳的 py 不赌壳有 bs4。

## ⚠️ 详情页 URL 拼接坑

第一版 `f'{host}/?play-{vid}-{pg}.html'` 少了末尾 `-` → 详情 404/空。卡片 href 是 `/?play-56117-1-.html`（`{vid}-{pg}-` 双分隔），重拼必须保留：`f'{host}/?play-{vid}-{pg}-.html'`。

## 验证

- init 1.75s（域名发现 0.9s + 分类 81 个）/ homeContent 0.96s 28 条 / categoryContent 0.99s / detailContent 0.89s 播放链接已替换
- 交付提醒：删旧文件再导入、ext 留空（代码自动发现域名）

# 拼多多.py 播放链路修复：data-preview 错位 + 分片 CDN 排查（2026-08-24）

`/opt/data/archive/xbpq资料/拼多多.py`（json 转 py，data-preview 直链站）。本文件记录**"列表解析全绿但用户点播放失败"**的根因与修复，以及播放链路逐级排查法。

## ⚠️⚠️ 播放不了根因：详情页第一个 data-preview 是推荐位/别的视频

列表解析出的播放链接完全正确（替换 .com 后 200、子流 200、分片 200），但用户点击播放失败。

**根因**：detailContent 请求详情页 `/?play-{vid}-{pg}-.html` 后 `re.search(r'data-preview=...')` 抠到的是详情页里**推荐位/其他视频**的 data-preview，不是当前视频——列表首条 m3u8 是 `20251119/qLW7tAtU`，详情页抠到的却是 `20251009/sQRi8ZQR`。播放器拿到错误视频链接（或拿不到），表现为"播放不了"。

**正解 = 列表即播放，vod_id 编码 m3u8，detailContent 不再请求详情页**（与 json 版行为完全一致——json"链接"字段=列表项 data-preview，点击直接播，`;;z` 直接播放）：

```python
# _parse_videos 里
vods.append({
    'vod_id': 'm3u8:' + play_url,   # ★ vod_id 直接编码播放链接
    'vod_name': title,
    'vod_pic': pic,
    'vod_play_from': '正片',
    'vod_play_url': '正片$' + play_url,   # 列表即带播放
})

# detailContent：m3u8: 前缀直接返回，绝不二次解析详情页
def detailContent(self, ids):
    vid = ids[0] if isinstance(ids, list) else ids
    if isinstance(vid, str) and vid.startswith('m3u8:'):
        play_url = vid[5:]
        return {'list': [{'vod_id': vid, 'vod_name': '拼多多视频',
                          'vod_play_from': '正片', 'vod_play_url': '正片$' + play_url}]}
    return {'list': []}

# playerContent：parse=0 免嗅直链 + header（兼容 m3u8: 前缀）
def playerContent(self, flag, id, vipFlags=None):
    url = str(id or '')
    if url.startswith('m3u8:'):
        url = url[5:]
    return {'parse': 0, 'playUrl': '', 'url': url, 'header': self.header}
```

**通用规则：json"链接"字段直接是 m3u8（data-preview/data-play-src 类）时，py 必须列表即播放（vod_id 编码 m3u8），不要设计"详情页二次解析"**——详情页首个播放属性几乎都是推荐位。

## ⚠️ 播放链路排查必须测到底（主 m3u8 200 ≠ 能播）

拼多多播放链路：主 `https://ckbhm3u8.com/.../index.m3u8`（200）→ 子流清单（200）→ **分片伪装 `.jpg` 后缀 + AES-128 加密**：

```
#EXT-X-KEY:METHOD=AES-128,URI="https://ckts2.top/.../key.key"
https://ckts2.top/.../gSyrwNJQ.jpg    ← 内容实际是 AES 加密视频流
```

- **分片/key 在另一 CDN 域名（ckts2.top），不在用户替换规则（ckbhm3u8.vip→com）覆盖范围内**——用户替换规则只保主 m3u8 域名，分片域名独立
- 排查"播放不了"逐级测：主清单 → 子流清单 → 分片/密钥域名（手机浏览器能下载 key.key 16 字节 = CDN 通）。**分片域名手机不可达则整源播不了，与 py 代码无关**
- 对照测试定位：json 版能播 + CDN 通 → 问题在 py 播放链路细节（本案例 = data-preview 错位）；json 版也不能播 → 站点 CDN 问题

# 拼多多.py 教训补遗（2026-08-24 第二轮，json 转 py 交付后多轮反馈）

## 1. 所有类型 ≠ 所有标签（json"数组"字段按分类指定）

用户反馈"所有类型和所有标签怎么是一样的？你看下json文件"——我第一版把两个 folder 都解析成了 fenlei 列表。json 的 `数组` 字段为每个分类单独指定截取区：

- **所有类型** → `?categories={catePg}.html` 页面，数组区 `<div class="collapse show">&&<div class="content__button">`，分割前 `<div class="models-wost__col">`，**36 个分类带图**（ic-img.usite.pro/categories/*.jpg），标题 `<center>&&</center>`，链接 `/?fenlei={分类名}` → folder 项 `dir_fenlei:{名}`
- **所有标签** → `?tags-ch-all.html` 页面，数组区 `<center>&&</center>`，分割前 `<a class="buttons black">`，**245 个标签**，标题 `title="&&"` 属性，链接 `/?tag={标签}` → folder 项 `dir_tag:{名}`

**教训：json 转 py 时逐分类对照 json 的数组/标题/链接字段（`||分类--规则` 段落），每个分类的截取锚点都不同，不要图省事统一用同一个解析函数抓 fenlei。**

## 2. 删掉吃屎喝尿分类

用户要求删除。json 分类 `所有视频#推荐类型#所有类型#推荐标签#所有标签#吃屎喝尿$吃屎喝尿#自定义词条$屎` 里吃屎喝尿是独立词条分类。用户第二轮明确"删掉吃屎喝尿"→ 从 self.classes 和 categoryContent 分支同时删（分类删除要同步清理路由分支，同 8度 删分类教训）。

## 3. 自定义词条默认打开第一个

用户反馈"词条默认打开第一个"。custom 分类无筛选参数时**不要返回空 list**，而是 `word = '丝袜'`（filters 第一个词条）直接搜索返回 28 条。用户打开"自定义词条"分类立即看到内容，而不是先弹筛选选择。

词条换新（用户"默认的那几个我不喜欢重换几个"）：先逐个 GET `?search={词条}&p=1` 验证 `data-preview` 计数 >0 再写进 filters。实测丝袜/黑丝/白丝/制服/护士/教师/空姐/口爆/颜射/自慰全 28 条。

## 4. 所有视频页标题是站点懒加载（无接口）——确认无法修复

用户三问"所有视频还是不显示名字"。彻底排查结论：

- 首页/标签页/搜索页的 `<p class="mb-1"><a href="...">标题</a></p>` **有标题**（服务端渲染）
- 所有视频页 `?video={pg}.html`、分类页 `?fenlei={名}` 的同一标签**为空**（`<a href="..."></a>`）——标题由 JS 懒加载填充
- 找接口：jiazai.js 只做 hover 预览（data-preview 加载 m3u8 视频），main.min.js 是 bootstrap，trku.js 是弹窗，`/ai/s/s/sum.php` 是统计；`?k=` 是搜索建议 JSON；`/?play-{id}-1-.html` 返回首页列表（无详情页概念）；`/?id={id}` 是 yzmplayer 播放页但 `config.title` 也是空
- **json 版在这些页显示的同样是数字 ID**——json 标题字段第二备选 `<p class="mb-1"><a href="/?play-&&-1-.html">` 就是截取 `play-` 和 `-1-` 之间的 ID

**结论：站点限制，向用户说明即可（"json 版同样显示 ID"），不要继续找接口浪费时间。**
